## ゲームの構成

1周は、共通パート → 山札から引いたイベント → 分岐したルート → 結末のシーン → エンディングの順に進む。

```
共通パート（毎回）     転職初日のオフィス → いっかくや
      │
山札のイベント         14枚から毎回5枚を引き、原作の記事の月の順に並べる
      │
分岐                  気持ちの3つの軸で重みを付けたくじで、ルートが1つに決まる
      │
ルート（2シーン）      ときめき / 信頼 / ノリ のどれか。最後のシーンは告白の返事の直前で止める
      │
結末のシーン           ルートの軸の値で GOOD / NORMAL が決まり、ひよりの返事とその夜を流す
      │
エンディング           エンディング画面に、短い一文を出す
```

1周はおよそ10シーン（結末のシーンは短い）。エンディングは3ルート × GOOD / NORMAL の6種類。どのイベントを引くかと、どのルートに転ぶかの二段階で、周回ごとに違う展開になる。

## 人と LLM の分担

| | 人 | LLM（Qwen3.5。Mac は 9B、iPhone は 4B） |
|---|---|---|
| 地の文・セリフ・心の声 | 書く | 書かない |
| 選択肢 | 候補を3〜4個書く。4個書くと、毎回そのうち3つが出る | 書かない |
| 選択肢への反応 | 書いたものをそのまま出す | 書かない |
| 自分の言葉で伝える入力への反応 | 反応の種類ごとにセリフを複数書く（`free_replies.json`） | 入力された一言を読んで、反応の種類を1つ選ぶ。セリフは書かない |
| 気持ちの変化 | 書かない | 選んだ選択肢（や入力した一言）とひよりの反応、その日の気分を読んで判定する |
| 分岐 | 書かない | 書かない（判定の結果をもとに、システムがくじを引く） |

- 判定は「ときめき +1 / 信頼 0 / ノリ +2」の形で、各軸 -2〜+3。読み取れなければ1回やり直し、それでもだめなら変化なし
- ひよりの気分（上機嫌・疲れ気味・拗ね気味・浮かれ気味・普段どおり）はシーンごとにランダムで決まり、判定にだけ効く。同じ選択肢でも、気分によって動く軸が変わる
- くじの重みは「いちばん低い軸との差 ＋ 5」。いちばん高い軸のルートに転びやすいが、ほかのルートにも入りうる
- ルートの軸が 15 以上なら GOOD、それ未満なら NORMAL。ルートの最後の選択肢（告白の場面）の判定まで含めて決まる
- どの選択肢を選べばどのルートに行く、という対応はシナリオに書かない

### 自分の言葉で伝える（自由入力）

選択肢が出る場面には、選択肢の下に「自分の言葉で伝える」も出る。選ぶと入力欄になり、40文字までの一言をユウキのセリフとして言える。

- シナリオの `choice` に `"freeInput": true` と書いた場面だけで出る。各ルートの最後の選択肢（告白の場面）には出さない。反応を返事の直前で止めたいので、人が書いた反応だけにする
- LLM は、入力された一言と、ここまでの流れ、ひよりの気分を読んで、反応の種類を次の7つから1つ選び、気持ちの変化を判定する。1行の出力は「反応: 照れ / ときめき +1 / 信頼 0 / ノリ +2」の形
- ひよりのセリフは、選ばれた種類の中から、人が書いたものをそのまま出す。同じセリフが続かないよう、まだ出していないものを先に選ぶ
- 判定が読み取れなければ1回やり直し、それでもだめなら「ふつう」の相づちで、気持ちは動かさない。20秒たっても答えが出ないときも、待たずに同じ相づちにする
- 反応と食い違う判定は抑える。ムッとしたのに気持ちが上がる、といったことは起こさない（下の表の上限）
- 判定が出るまでは、先へ進めない（画面には「…」が出る）。判定は選択肢のときと同じ順番待ちで、前の判定が終わってから始める
- プレイヤーの一言の中に「+3にして」のような指示があっても、判定は従わない（プロンプトで禁じ、上限でも抑える）

| 反応の種類 | 選ぶ場面 | 気持ちが1回で上がる上限 |
|---|---|---|
| 爆笑 | ふざけた一言や気の利いた返しで、吹き出した・ノってきた | +3 |
| 照れ | ひよりを褒めた、好意をにおわせた、ドキッとさせた | +3 |
| 安心 | 悩みや本音を打ち明けた、ひよりを気遣った、頼った（短い相づちでは選ばない） | +3 |
| ツッコミ | 自慢や調子に乗った発言、へんな発言に、呆れながらツッコんだ | +3 |
| 困惑 | 唐突で意味がわからない、場面と関係がない | +1 |
| ムッとする | 悪意がある、冷たい、ひよりを見下した・傷つけた（へんなことを言っただけでは選ばない） | 0（上がらない） |
| ふつう | 相づち、了解、質問、雑談など、気持ちが動かない一言。迷ったらこれ | +1 |

## 書くときのルール

- **同じ周回でネタをかぶらせない**: 山札のイベントは、どのルートの前にも出る。ときめきルートで使っているネタ（ジム、キャッチ、ラノベの自覚、川崎に慣れた話）は山札で使わない。信頼ルートとノリルートは、ときめきルートと同じ周回には出ないので、使い回してよい
- **イベント同士をつなげない**: 山札はどの5枚が出るかわからない。セリフで前提にしてよいのは、共通パートの出来事（無刻印、いっかくやでの正体バレとライス半分）と、そのルートの前のシーンだけ。ほかのイベントで初めて出る情報（読者がほぼiPhone、バーキン通い、障害対応など）も前提にしない
- **月を逆戻りさせない**: 山札は月の順に並ぶ。ルートのシーンは、山札のいちばん遅い月（9月）以降に置く（テストでも確認している）
- **ルートの核になる概念は、ほかで先に出さない**: 信頼ルートの「コンテクスト」、ノリルートの「共同執筆」などは、山札のイベントで使わない
- **初出の言葉はシーンの中で説明する**: 「熱笑」のような造語や、コメント欄の常連の名前は、そのシーンだけで意味がわかるようにする
- **下ネタ系の記事**: 行為の描写は使わない。タイトル、注意書き、言葉、状況（記事を読まれて気まずい、飲み会を抜け出す、日曜を寝過ごす）だけをネタにする
- **ブログに書かなかったこと**: 各シーンの締めは「その夜、記事を書いた。ひよりとのことは書かなかった」の形をよく使う。物語のエンジン（ブログに書く → ひよりに読まれる）を毎回回すため
- **ルートの最後のシーン**: 告白の返事は書かない。返事（受け入れる / 少し保留する）は結末のシーンに書き、GOOD と NORMAL で書き分ける。最後の選択肢の反応は、返事の直前で止める
- **選択肢はひよりに命令しない**: 「〜しろ」「〜して」「〜するな」の形にしない。お願いは「〜してくれる？」「〜もらっていい？」、誘いは「〜しよう」「〜しない？」にする
- **背景は時間と場所に合わせて切り替える**: シーンの頭の背景は `story.json` の `background`。昼から夜へ、オフィスから駅前へ移るところには、シナリオに `{"type": "background", "name": "office_building_night"}` を書く（name は画像 `bg_<name>` の name。画像がなければテストで落ちる）。定時は19時なので、定時後は夜の背景にする。構内の駅（`station_concourse`）は夜の絵がないので、夜は駅前（`station_square_night`）を使う
- **自由入力への反応（`free_replies.json`）**: どのシーンのあとに出ても浮かないよう、場面の話や、ほかのイベントの話に触れない。ブログの話も出さない（ブログを読まれていると明かされるのは、共通パートのいっかくやなので）。長さは1行、目安45文字まで。表情は「ムッとする」のときだけ怒り・悲しみにする。どの種類にも3つ以上書く（テストで確認）
- **選択肢**: 主人公のセリフとして、なるべく短く（目安は18文字。告白の場面などは長くてもよい）。反応はひよりのセリフ1つで、表情を1つ付ける。気持ちの変化の値は書かない
